Everything produced by a scan, and the current posture, lives here. Nothing
else does. Policy and controls are described in `docs/05-SECURITY.md`.

## Layout

```
security/
├── README.md            this file
├── POSTURE.md           current posture. Regenerated by every scan
├── policy/
│   ├── grype.yaml       grype configuration and failure thresholds
│   ├── trivy.yaml       trivy configuration
│   └── allowlist.yaml   time boxed exceptions, each with an owner and expiry
├── reports/
│   ├── YYYY-MM-DD-HHMMSS/
│   │   ├── index.html   the human readable report with suggested fixes
│   │   ├── summary.json machine readable roll up
│   │   ├── grype-*.json per target scanner output
│   │   ├── trivy-*.json
│   │   ├── pip-audit.json
│   │   └── npm-audit.json
│   └── latest/          symlink to the most recent run
├── sbom/
│   └── *.spdx.json      one SBOM per image, per build
└── reviews/             automated code review reports, see ADR-0011
```

## The rule

**Zero vulnerabilities. Not zero critical, not zero high. Zero.**

A finding that genuinely cannot be fixed goes in `policy/allowlist.yaml` with a
named owner, a reason, and an expiry date no more than 90 days away. It never
goes in by lowering a threshold, because a lowered threshold is invisible and
an expiring allowlist entry is not.

## Why the nightly scan matters more than the build scan

A vulnerability published tomorrow against a dependency shipped today turns
yesterday's green build red, with no change to the code.

A pipeline that scans only at build time therefore reports zero forever while
the deployed image degrades silently. The nightly job scans **the digest that
is actually running in each environment**, and `POSTURE.md` reflects that scan.

## Running a scan

```bash
make security-scan        # everything, writes a timestamped report
make security-report      # rebuild the HTML from the latest run
make security-fix         # propose and apply fixes on a branch, then re scan
make dep-check pkg=<name> # admission gate before adding a dependency
```

## Tools

| Tool | Scans | Why this one |
| --- | --- | --- |
| `grype` | Container images and filesystems | Required. Fast, accurate, and the fixed version field drives the auto fix |
| `syft` | Generates the SBOM | grype's companion. The SBOM is the audit artefact |
| `trivy` | Images, plus Terraform misconfiguration | Second opinion on vulnerabilities, and covers infrastructure as code |
| `pip-audit` | Python dependencies against OSV | Catches advisories before they reach an image |
| `npm audit` | Frontend dependencies | Same, for the frontend |
| `gitleaks` | Secrets in the repository and its history | A leaked credential is not a vulnerability class a CVE scanner finds |
| `cosign` | Signs images, attaches the SBOM attestation | A financial services audit asks for provenance, not just a scan |

Two vulnerability scanners is deliberate. Their databases differ, and the
difference is exactly where a missed finding lives.
