Deploying it

Eight steps across three places. The order is not obvious: the two role stacks go first, because they trust a hub role by name, not by ARN.

How it collects

A queue of small jobs, not a nightly batch. One account failing never fails the run.

3

How a screen reads

Every answer carries how old it is and how much of the estate it covers, so a partial view is never shown as a total.

4

What protects it

There is no password or access key anywhere in the system. Every read into your accounts is a short lived session it has to ask for.

5

What it is made of

Six parts stacked, each allowed to use the ones below it and never the ones above. A test fails if that is broken.

One thing to know before trusting any of this

None of it has ever run against a real AWS account. Every test, the demo data and every screen run against a stand in that satisfies the same eleven interfaces as the real AWS adapter. That is a deliberate design property, and it is also the largest unknown: matching interfaces prove the two agree with each other, not that either agrees with AWS.
